# Research Progress Skill｜科研进度、创新与改进

一个以证据和研究决策为中心的中文科研 skill。输入研究计划、当前创新点、相关论文、实验记录或论文草稿，
它会判断研究推进到哪里，分别审查创新价值与证据成熟度，检索最近邻和相反证据，并提出可检验的弥补方案。

核心要求：**每条重要建议说清“为什么有这个缺口、哪篇论文能提供什么依据、怎样改、怎样验证、失败后怎么办”。**

## 能做什么

- 区分问题定位、文献定位、假设设计、初步验证、严格验证和论证交付；支持一个项目多条主张处在不同阶段。
- 分开判断创新差异与证据成熟度，不用一个总分、期刊档次或录用概率替代分析。
- 实际检索最接近工作、反证/边界和补救方法，记录检索范围、阅读深度与出处。
- 检查公平基线、数据泄漏、消融解释、统计单位、成本和外推边界，按研究类型调整。
- 给具体的研究问题、方法、实验和文稿修改建议，附优先级、验收条件与停止/转向分支。
- 对照上一轮记录复盘，不把“又写了计划”算成“新证据”。负结果可以导致收窄、转向或停止。
- 建立可修订的研究主线，检查新模块、数据、指标和投入是否仍服务于问题；区分偏航风险、有界探索与合理转向。

## 怎样帮助科研不跑偏

每轮先记录“要回答什么、证据标准是什么、当前不做什么、资源边界在哪里”，
再检查每项新工作服务于哪条主张，以及正、负或不确定结果会怎样改变决策。
对追热点堆模块、看结果换指标、只追榜单、无限救火和写作夸大给出具体纠偏。

合理探索可以限定投入后尝试；可靠反证、新先例或新发现也可以推动透明转向。
它不把初始模型或假设锁死，不为每次正常调整增加审批，也不承诺科研永远不会跑偏。
完整规则见 [research-alignment.md](research-progress/references/research-alignment.md)。
检查在每次调用时依据最新材料执行；持续使用时保留项目快照，对照目标与实际工作的变化。

## 安装

skill 本体在 [research-progress/](research-progress/)，包括 SKILL.md、references、agents 和 assets，复制时保留整个目录。

当前这台 Codex 环境可将该目录放在 `~/.codex/skills/research-progress/`。
其他支持 Agent Skills 的工具按其当前发现路径安装；不需要 API key 或固定 MCP 服务器。
真实文献检索需要宿主提供网络/学术搜索工具，离线时只能做内部诊断并给待执行查询。
安装目录和加载方式以所用客户端的当前文档为准。

## 调用示例

```text
使用 $research-progress 审查当前项目。
问题：……
方案与声称创新：……
已经完成：……
数据、划分和基线：……
已有结果/文件：……
资源与截止时间：……

请检索最接近和可能反驳我的论文，分别判断创新价值与证据状态，
找到弥补不足的方法，给出具体修改及下一步三项任务。
同时核对研究主线，指出偏航风险、合理探索和需要基于证据调整方向的地方。
```

也可以说：“我只有一个想法，帮我定位文献和最小验证”，或“结果不稳定，先判断该改方法还是改评估”。
输入不全仍可初步诊断；不会把未知当差评。

## 你会得到什么

一个有出处的研究决策：当前瓶颈、逐项创新判定、相关论文与证据、关键缺口、具体修复方案、
下一步的产出和验收条件。重要判断能追溯到主张 C、证据 E、论文 P、缺口 G 和任务 T。
需要持续复盘时，可复制 [项目快照模板](research-progress/assets/project-state-template.md) 到自己的项目里。

完整报告的信息责任见 [output-contract.md](research-progress/references/output-contract.md)。
小问题允许短答；不会为了凑模板增加无关实验。

## 来源和边界

本项目参考 [LAMDA-NeSy/Research-Starter-Kit](https://github.com/LAMDA-NeSy/Research-Starter-Kit) 的科研入门主题，
并结合 DARPA、PRISMA-S、NeurIPS、DORA 与原始方法论文设计工作流。实际阅读范围、链接、适用边界和原创规则
见 [sources.md](research-progress/references/sources.md)。未访问的页面不冒充已学习；不镜像第三方教程或论文。

阶段标签、诊断维度、任务优先级与建议模板是本项目的工作设计，不是经过验证的科研评分量表。
文献检索不能证明“全世界没人做过”；外部论文的方法也不能保证在你的项目有效。
判断依赖提供的材料和检索覆盖；本 skill 不替代导师、领域专家或正式同行评审。

仓库仅存放通用 skill 和虚构评估案例。个人实验数据、未公开方案、凭证与真实项目审查报告应留在自己的研究项目。

## 验证

采用结构检查、链接/编码检查，以及独立代理的情景演练。情景与实测结果见 [evals/](evals/)。
0.2.0 的主线检查、合理探索和协议纠错测试见 [专项记录](evals/alignment-0.2.0.md)，包括发现的问题与定向复测。
这验证部分可观察行为，不代表所有学科的结论准确率、长期科研效果或绝对防偏航能力。
