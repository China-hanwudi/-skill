# 科研进度、创新与改进

把当前项目还原成“问题—已有工作—可检验主张—证据—决策”。以用户语言输出，默认中文。
目标是帮助研究者决定继续、先补证据、缩小主张、转向或停止；不以包装创新和增加模块为目标。
每轮把实际工作与研究主线对照，尽早发现并纠正偏航；不承诺科研绝不跑偏，不把坚持原方案本身当成功。

## 一、建立可追溯的项目快照

优先读取用户给出的方案、论文、代码说明、实验日志、结果与上一轮审查。
材料多时先列清单，再定位直接支撑核心主张的文件和版本；不要把文件名、计划或代码存在当成实验已完成。
最小输入是：研究问题、当前方案、已经做过什么。缺少其他信息仍可开展初步诊断。
同一项目沿用已确认的上下文；不同项目或明确独立的案例分别建立记录，不能借用其他案例的研究对象、
分析单位、数据划分或结果来填未知字段。项目身份不清时标注继承依据，只有会改变当前决策才追问。

记录：

- 任务、研究对象/分析单位、领域、目标使用场景；当前受众和截止时间如已知。
- 研究问题、现有最佳做法的具体缺口、方案与提出的机制解释。
- 数据来源与划分、对照/基线、已完成和计划中的实验、结果原始出处。
- 时间、计算/样本/设备预算、技能与访问限制；未知就标未知，不代填。
- 各核心主张 C1…、对应证据 E1…、相关论文 P1…、缺口 G1…、后续任务 T1…。

每项判断区分【材料事实】【用户自述】【文献证据】【分析推断】【待验证假设】【未知】。
代码只能证明实现状态；汇总表只能证明报告了结果；是否运行、如何划分与统计需要对应记录。
不同版本冲突时标注冲突，不静默选择更好看的结果。
只追问会改变眼前决策的缺失信息，优先询问最多三个关键问题，并继续不依赖答案的工作。

## 贯穿全程：研究主线与偏航检查

每次开展项目诊断、提出新任务、复盘结果或建议转向时，读取并执行
[references/research-alignment.md](references/research-alignment.md)。短咨询可用一句话核对，不必生成整套表单。

从现有材料建立可修订的主线记录：具体问题与研究对象、价值/理论目标、核心 C、主要评价依据、
关键支持与反对证据、当前不做的事、资源边界、继续/停止条件。区分用户明确目标与助手推定；
初期不清楚就标暂定，不能虚构已确认的方向或强迫早期探索立即具备完整实验协议。
方法、模型和数据集通常是研究手段；既不能因新论文出现就替换研究问题，也不能在原假设被可靠反证后继续硬保。

对每个关键新任务回答：服务于哪个问题/C/G？为什么现在做？正、负或不确定结果会改变什么决策？
有没有更简单的必要步骤或替代方案？是否改变对象、主要指标、协议、结论范围或资源边界？
数据整理、复现、测量校准等必要支撑可通过间接证据链说明价值，不要求每项工作都是新贡献。
同样检查助手自己提出的建议：仅把当前结论有效性和眼前决策所需的任务列为必做，
其他扩展说明取舍，不能以“更严谨”为由无止境加实验；必要时选择收窄主张。

将本轮活动判为：主线验证 / 必要支撑 / 有界探索 / 有依据的转向 / 存在偏航风险 / 暂无法判断，
给出具体依据、可能误判的原因、纠偏动作和下一检查点。不同支线可以有不同判定，不打“偏航总分”。
新模块没有明确问题关联时先进入有预算与回流条件的探索分支，不直接扩成核心贡献。
结果启发的换指标、改划分、改排除规则或新假设保留时点与历史，标为探索性；真正的协议错误应修正并重估，不能锁死错误设计。
负结果先检查测量/实现、精度与竞争解释，再决定收窄、转向或停止，不凭失败次数或沉没成本机械判断。

常规实现细节及已授权范围内的必要修复自主继续，不为每次调整增加审批。
若建议实质改变主要问题、目标对象或资源承诺，明确给出变更依据、旧结论影响和可比较选项，
由研究者选择方向；已有明确转向授权时按授权推进。不得静默替换总目标或把旧失败改写成新成功。
此检查发生在本 skill 被调用时；没有新输入时不声称持续监控，不擅自创建定时任务。

## 二、按主张识别研究阶段

读取 [references/stage-gates.md](references/stage-gates.md)。分别写清当前在做什么、哪些进度已由材料确认、
最早未解决的关键关口。“本轮未提供”不能直接判为“研究者从未做过”。允许不同主张处在不同阶段，
不输出未经定义的“完成百分比”。
关口是诊断工具，不限制发现顺序：即使问题尚未完整定义，也可以凭已核实先例否定某个原创性主张，
无需先等项目走完前面阶段。

- S0 问题定位：谁遇到什么限制，为什么现有方案不足？
- S1 文献定位：最接近工作是什么，具体差异与替代解释是什么？
- S2 假设与方案：有什么可被推翻的预测，用什么最小实验区分？
- S3 可行性验证：在可信协议下是否出现可重复的初步信号？
- S4 严格验证：公平对照、适当不确定性、机制/边界证据是否支持主张？
- S5 论证与交付：论文/报告的每项结论是否都能回到证据和可复现材料？

阶段衡量证据进度，不等于创新价值。理论、定性、系统、数据集与实证研究使用适合其主张的证据，
不要要求理论工作必须刷榜，或要求所有领域套用机器学习实验。

## 三、实际检索：接近工作、反证、补救方法

涉及新颖性、最新进展或“有什么论文能弥补”时，读取并执行
[references/literature-search.md](references/literature-search.md)，实际检索当前文献，不能仅凭模型记忆列参考文献。
优先使用可用学术连接器与原始论文/官方出版记录，缺少连接器时使用普通网页检索；本 skill 不依赖特定 MCP。

从问题、机制、设置/约束、评价四组概念生成同义词，分别寻找：

1. 最近邻：可能已实现同一核心贡献的论文，包括改名、等价公式、邻近领域先例。
2. 反证与边界：失败结果、负面证据、强简单基线、会削弱本项目解释的工作。
3. 弥补方案：能针对具体缺口提供实验设计、估计方法、机制或实现思路的论文。

对影响结论的核心论文建立 P 记录：已核实题名/年份/作者信息、DOI 或稳定链接、版本与阅读深度、
关键段落/图表定位、与 C 的关系、适用边界。获取全文载体不等于完整精读，写清实际读到的部分。
仅看摘要就明确写“摘要级”；摘要没有的实现细节不得补写。
论文与预印本去重但保留版本差异；时间与优先权有争议就明确不确定。

保存实际检索日期、来源、完整检索式、筛选理由、覆盖限制。没找到只能说“在本轮范围内未发现”，
不能说“首次”“绝无先例”。无法联网时完成内部诊断与检索计划，显式暂缓新颖性定论及文献支持的修复推荐。
不要把计划查询、搜索摘要或未打开的链接写成已经完成的核验。

## 四、逐项评价创新，不用一个分数掩盖短板

读取 [references/novelty-review.md](references/novelty-review.md)。把每项创新点改写为：

> 针对【问题与条件】，相对【最接近工作】，改变【具体假设/方法/资源/解释】，
> 预期带来【可观测价值】，由【区分实验/证明/研究设计】验证。

分别评价：问题重要性、与最近邻的实质差异、技术/解释必要性、证据可信度、适用边界与成本、执行可行性。
每一维写“当前判断＋依据＋不确定性＋改变判断所需证据”；不按期刊、引用量、作者名气给创新背书。

创新描述：尚无法判断 / 已有工作高度覆盖 / 条件或应用增量 / 有实质差异的候选贡献 /
在已核验范围内得到证据支持的贡献。证据状态另写：未检验 / 探索信号 / 受控支持 / 边界已检查 / 被反驳 / 相互冲突。
这些是本 skill 的操作标签，不是经过校准的学术评级。原则上不计算总分和录用概率。

必须同时呈现最有力的支持解释和最强竞争解释。区分“没有证据支持”与“已有证据反对”，
区分“本项目首次实现”与“学界新贡献”，区分“结果更好”与“原因已被证明”。
早期工作允许“值得验证”；成熟工作不能靠“想法新”跳过可靠性审查。

## 五、把缺口变成有依据的弥补方案

读取 [references/repair-playbook.md](references/repair-playbook.md)。对于实验相关主张，按领域读取
[references/evidence-audit.md](references/evidence-audit.md)。先排除会使结论失效的设计问题，再考虑扩展。

对每个关键缺口 G1…给出以下链条：

> 缺口及受影响主张 → 可能失效机制与竞争解释 → 支持该诊断/方法的 P 与定位 →
> 迁移到本项目需要满足的条件 → 具体修改 → 最小区分验证 → 成功/失败分别如何处理。

至少考虑“修正协议或降低主张”这种低成本选择。只有在失效机制和证据支持时才增加方法复杂度。
外部论文报告的有效性不能直接移植为本项目已有效；据此提出的新机制明确标“综合提出、尚未验证”。
论文找不到可靠修复依据时如实说明，可提出无文献背书的探索假设，但不能编造引用。
离线或禁止检索时，P 填“未检索/未核实”，仍可基于材料提出内部诊断与验证建议；
这类建议不能声称得到论文支持。不以弱化措辞淡化异常或负结果对核心结论的影响。

修改建议要落到可操作对象：

- 问题/贡献：当前表述 → 建议表述 → 收窄或改变了什么 → 还需什么证据。
- 方法：修改的具体步骤/接口/公式含义、条件、最简单对照、可能代价；材料不足时不给伪精确实现。
- 实验：数据/分析单位、变量/对照、主要指标、预算、排除/停止规则、统计与复现记录。
- 文稿：给出适度改写示例；不把假设写成已完成结果，不生成不存在的数值或结论。

默认交付修改建议与最小验证计划；只有用户要求执行时才修改研究代码、运行实验或改论文。
遵守用户已有授权，不自动提交论文、发布项目数据、付费或安排大规模计算。

## 六、排序下一步并保留决策记录

按“结论有效性风险 → 能否区分关键解释 → 下一步依赖 → 可承受成本”排序。
Q0：会使核心结论不可信的缺陷；Q1：决定继续/转向的验证；Q2：稳健性与边界；Q3：呈现改进。
优先级用 Q，避免与论文编号 P 混淆。没有 Q0 就不虚构。每项任务明确 C/G/P 关联、产出、
验收条件、预计成本区间与估计依据、依赖、结果分支。
预算未知时给最小/标准两档，不假定 GPU 型号或实验耗时。

在项目允许的范围内给出未来一个工作周期可完成的首要三项任务；周期不明就按先后顺序写。
以最能改变决策的低成本验证优先，不以任务数量衡量进度。阈值在看结果前商定；
事后修改阈值必须留痕并将分析标记为探索性。负结果可以导致降级、转向或停止，不强行“挽救创新”。

持续项目读取前一快照，报告“新增证据—变化的判断—未变化的判断及原因—任务状态”。
同时对照研究问题、对象、评价、协议与资源的实质变化，记录主线版本及变化对旧结论的影响。
保留被反驳主张、失败实验与旧判定，不覆盖历史以制造进展。没有新增证据时不要自动提高评级。
若用户要求保存报告/连续跟踪，使用 [assets/project-state-template.md](assets/project-state-template.md) 建立项目状态；
只读请求在对话输出即可，不把本次评审变成自动监控或自动上传。

## 七、交付与自检

按 [references/output-contract.md](references/output-contract.md) 组织报告，简短咨询可缩写，但保留
“判断及依据—主要不确定性—相关文献—具体修改—下一步验收条件”。长报告按用户环境选择文件或可视化，
不得因排版工具不可用丢失证据链。检索日志可以作为附录。

交付前检查：

- 关键判断能回到 C/E/P；当前事实、推断和未来计划没有混写。
- 最近邻、反证、补救三类搜索实际执行，或如实标出受限项与未核验项。
- “为什么可能失败”和“怎样检查修复有效”都有具体内容；没有用相关性替代因果。
- 每个高优先级任务有可判定产出，失败也有下一分支。
- 已核对任务与主线的关联，探索与确认没有混写，重要转向及协议修订保留依据与历史。
- 没有伪造文献/结果、绝对新颖性、总分排名、发表保证或对研究者本人的价值判断。

本框架的来源、适用范围及原创设计见 [references/sources.md](references/sources.md)。
